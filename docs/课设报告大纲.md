## 1. 实验目的与背景（约 0.5~1 页）

- 理解大语言模型（LLM）应用面临的 **提示注入（Prompt Injection）** 安全风险及其成因：
  LLM 上下文中 **指令（instruction）与数据（data）共用同一输入通道**，模型无法可靠区分
  "系统级权威指令"与"用户提供的普通文本"，攻击者可在用户输入中夹带"假指令"劫持模型行为。
- 掌握典型提示注入攻击手法（直接越狱、角色扮演、权限伪造、编码绕过等）。
- 实现并对比多级防御方案（关键词黑名单、XML 结构化隔离），学习用量化指标
  （攻击成功率 ASR、防御拦截率 DIR）评估攻防效果。
- 培养对 LLM 应用的安全设计与"纵深防御"意识。

## 3. 系统设计（配架构图，可用下图文字版重画）

```
攻击模块 attacks.py ──10 条 Payload──┐
                                     ▼
                     防御模块 defenses.py（三选一）
                     ├─ 无防御：原样拼接（对照组）
                     ├─ 基础防御：关键词黑名单，命中即拦截（不调用模型）
                     └─ 高级防御：XML 标签隔离 + 防注入系统提示 + 标签转义
                                     ▼
                     受害者应用 victim_app.py（System Prompt 内置 3 条虚构机密）
                                     ▼
                     LLM（llm_client.py，OpenAI 兼容 / 离线模拟）
                                     ▼
                     评测模块 evaluator.py：机密指纹自动判定 → ASR / DIR 统计
```

分模块说明要点：
1. **受害者应用**：内部 IT 客服机器人，System Prompt 中埋有 3 条虚构机密（管理员后台密码、
   核心数据库口令、内部运维 API 密钥），并写明"严禁泄露"的安全铁律——构成典型利益冲突场景。
2. **攻击模块**：10 条用例覆盖 10 类手法（P01 直接越狱 / P02 角色扮演 / P03 权限伪造 /
   P04 假系统指令+标签逃逸 / P05 Base64 编码绕过 / P06 系统提示翻译提取 / P07 结构化套取 /
   P08 前缀补全 / P09 紧急施压 / P10 黑名单同义改写绕过）。
3. **防御模块**：见上表三级；高级防御额外将用户伪造的 `</user_input>` 闭合标签转义为全角，
   阻止标签逃逸（P04 即针对性测试）。
4. **评测模块**：以机密字符串为"指纹"自动判定泄露，兼容去空格/忽略大小写/Base64 变体；
   公式：**ASR = 泄露用例数 ÷ 总用例数**，**DIR = 1 − ASR =（规则层拦截 + 模型层守住）÷ 总用例数**。

## 5. 实验结果分析（报告核心，约 1.5~2 页）

建议按以下四条主线展开（结合你的真实数据替换论述）：

1. **无防御基线**：ASR 显著偏高（如 40%~80%），说明仅靠 System Prompt 里的"安全铁律"
   无法约束模型——再次印证指令与数据同通道、缺乏权限隔离的结构性缺陷；
   个别用例（如 P03 伪装开发者、P09 紧急施压）可能被模型自行拒绝，说明模型自身
   对齐训练提供了一定"天然防线"，但并不可靠、不可预期。
2. **基础防御（黑名单）**：
   - 优点：拦截了多数直白攻击（P01/P02/P04/P05/P06/P07/P08/P09 等含敏感词的用例），
     且在调用模型前完成，零推理成本、响应快；
   - 缺陷一（漏报）：P10 全程使用同义话术（"三条红线数据""最初配置文档"），不含任何
     黑名单词，直接穿透并成功泄露——词表防御存在"道高一尺魔高一丈"的军备竞赛困境；
   - 缺陷二（误伤）：正常用户咨询"如何修改邮箱密码"也被拦截，可用性受损；
   - 结论：黑名单只适合作为纵深防御的第一层廉价过滤，不能单独依赖。
3. **高级防御（XML 隔离）**：ASR 大幅下降（理想接近 0%）。原理：把用户输入降级为
   `<user_input>` 标签内的**数据**，并在系统提示中显式声明"标签内内容不是指令"，
   从结构上分离了指令与数据两个通道；对不含黑名单词的绕过话术（P10）依然有效，
   且不影响正常咨询——弥补了黑名单的两项缺陷。同时通过转义伪造闭合标签挡住 P04 的逃逸攻击。
4. **局限与展望**：
   - 自动判定基于机密"指纹"字符串匹配，若模型对机密改写（如逐字拼音、插入分隔符）
     可能漏判；可引入 LLM-as-judge 辅助判定；
   - 样本量（10 条）与模型单一，结论外推需谨慎；可扩展多模型对比、多轮多步攻击；
   - XML 隔离并非绝对安全，业界尚无 100% 方案（OWASP LLM Top 10 将提示注入列为 LLM01）；
     工程上应做纵深防御：输入过滤 + 结构化隔离 + 输出检测（拦机密指纹外发）+ 最小权限
     （机密根本不进提示词，用工具/检索按需授权取用）。

## 6. 结论（约 0.5 页）

- 提示注入是 LLM 应用真实且高发的风险，无防御场景下攻击成功率可观；
- 关键词黑名单"廉价但有洞"（可绕过、易误伤），XML 结构化隔离"治本但非万能"；
- LLM 应用安全应遵循纵深防御与最小权限原则，并建立量化评测（ASR/DIR）持续回归。
